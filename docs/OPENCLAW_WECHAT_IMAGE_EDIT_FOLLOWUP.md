# OpenClaw 微信机器人图片修改功能：后续实施说明

原计划中的微信动画表情名称读取也已取消，不再安排实施。

状态：已取消并停用（按用户要求关闭现有本地修图功能；方案文档保留作历史记录）
评估日期：2026-09-23（东京时间）

## 目标

为微信群里的 OpenClaw 微信机器人增加图片修改能力。群成员通过 `@机器人` 发起修图请求，说明修改要求并发送图片；机器人将原图和要求交给图片编辑服务，完成后把修改后的图片发回群聊。

图片识别与图片修改是两项不同能力：现有 Qwen/DeepSeek 负责理解对话或识别图片；实际生成修改图片需要接入专门的图片编辑模型，或部署本地图片生成工作流。

## 预期群聊流程

1. 群成员发送 `@机器人 帮我修图`、`@机器人 修改一下图片内容` 等明确的修图请求。
2. 机器人回复固定提示，例如：**“请说出修改需求并发送图片。”** 同时创建一个短时待处理任务。
3. 发起者在有效时间内再次 `@机器人`，描述修改要求并发送图片。文字和图片可以在同一条消息，也可以分开发送；实现时应允许图片先到或要求先到。
4. 机器人把该发起者的修改要求与图片配对，调用图片编辑后端。
5. 编辑成功后，机器人把结果图片发回群聊，并清除待处理任务；失败、超时或取消时，返回清楚的提示并清理状态。

## 群聊任务隔离与保护

- 待处理状态以 **群聊 ID + 发送者 ID** 为键，不能只按群聊保存，避免不同成员的需求和图片串单。
- 只有发起任务的成员在有效期内发送的图片可以进入该任务；建议初始超时设为 5 分钟。
- 收到第一张匹配图片后即锁定该图片，除非用户明确要求多图参考，避免后续图片意外替换输入。
- 任务成功、失败、取消或超时后都删除状态和临时文件。
- 编辑任务进入独立队列，避免阻塞普通文字对话、现有识图任务和其他群聊消息。
- 保留原图，不覆盖、不删除原图；输出作为新图片发送。
- 对群聊中的隐私图片应明确提示：云端方案会将图片发送给模型服务商；本地方案可让图片留在本机。

## 三种后端的成本与效率

### A. 本机 ComfyUI + SDXL 修补

- **费用：**没有按张 API 费用，主要是电费、模型存储和部署维护成本。
- **速度：**以当前硬件估算，SDXL 1024 图像修补热运行大致是数十秒；首次加载模型会更慢。这个区间是规划估算，不是本机实测结果，最终速度取决于模型、分辨率、采样步数、蒙版和节点流程。
- **效果与接入：**适合局部重绘、换背景、删除/添加对象等明确区域编辑。自然语言直接描述复杂变化时，通常需要选择合适的工作流；精确局部修改可能还需要分割或蒙版步骤。
- **隐私：**图片可以留在本机。
- **限制：**需要部署并维护 ComfyUI、下载模型、配置工作流和本地 HTTP 调用接口。显卡也会与 Ollama/Qwen 争用显存。

### B. Gemini 图片编辑 API

- **费用：**Gemini 3.1 Flash Lite Image 官方价格中，1K 输出图片约 **US$0.0336/张**；100 张约 US$3.36，另有少量输入与文本费用。标准 Gemini 3.1 Flash Image 的 1K 输出约 **US$0.067/张**。[官方价格表](https://ai.google.dev/gemini-api/docs/pricing)
- **速度：**Flash Lite 官方定位为低延迟图片生成和编辑模型，适合交互式场景；官方没有保证固定的端到端响应时间，微信侧还会增加下载、上传和回传时间。
- **效果与接入：**直接把原图和自然语言修改要求一起提交，交互实现较简单；支持图片编辑和多轮图片修改。[官方图片编辑说明](https://ai.google.dev/gemini-api/docs/image-generation)
- **隐私：**需要把输入图片上传到 Google 的 API。应确认 API 账户的数据使用条款和项目设置。

### C. OpenAI 图片编辑 API

- **费用：**当前 GPT Image 2.5 按图像输入/输出 token 计费，输入图片、分辨率和生成质量都会影响总价；需要根据 API 返回的 usage 统计实际单张成本。旧版 GPT Image 1.5 的官方 1K 方图输出参考价为中等画质约 **US$0.034/张**、高画质约 **US$0.133/张**，输入图像费用另计。新接入应以[当前 API 费用说明](https://developers.openai.com/api/docs/guides/image-generation)和实际 usage 为准。
- **速度：**云端处理，通常不需要本机加载大型图片生成模型；真实耗时取决于模型、画质、尺寸、服务负载及网络，官方没有固定端到端时延保证。
- **效果与接入：**提供图片生成与编辑 API，可用于把已有图片作为输入再编辑；需要单独配置 OpenAI API Key。[官方图片 API 文档](https://developers.openai.com/api/docs/guides/image-generation)
- **隐私：**图片会离开本机并发送给 API 服务。

## 本机硬件评估

本次只读检查到的主机状态：

- CPU：AMD Ryzen 7 9700X，8 核 16 线程。
- 内存：约 32 GB。
- 显卡：AMD Radeon RX 7700 XT，官方规格为 12 GB GDDR6 显存。[AMD 规格](https://www.amd.com/en/products/graphics/desktops/radeon/7000-series/amd-radeon-rx-7700-xt.html)
- Ollama：本机已有两个约 9B 的 Qwen 模型；检查时 `ollama ps` 没有显示驻留模型。机器人实际处理消息时，Qwen 可能会重新加载。
- WSL：OpenClawGateway 当前约 15 GiB 可用内存。若部署 ComfyUI，优先考虑 Windows 原生环境，避免受 WSL 内存上限影响；ComfyUI 当前文档列出了 Windows AMD ROCm 10.0 路线，并把 RX 7700 XT / 7800 XT 对应到 `gfx1101`。[ComfyUI 安装说明](https://github.com/Comfy-Org/ComfyUI)

### 资源冲突注意事项

RX 7700 XT 的 12 GB 显存可以尝试运行 SDXL 修补，但本地 Qwen 和图片模型可能争用显存。实施时应：

1. 将图片编辑放入独立队列，先限制同时运行的编辑任务为 1。
2. 编辑开始前检查显存/模型驻留状态；必要时卸载或等待 Qwen 释放显存。
3. 编辑完成后再恢复普通本地模型处理，避免大量群聊请求同时启动两个模型造成显存不足或响应变慢。
4. 先用一套固定的 1024 图像工作流做本机基准测试，再决定是否开放群聊使用。

## 推荐实施顺序

建议分两阶段推进：

### 阶段 1：快速验证交互

先接入 Gemini Flash Lite Image，完成“@发起修图 → 提交要求与图片 → 返回结果”的闭环。限制单个任务只处理一张图片、一次编辑，启用超时、隔离、失败提示和队列，记录每个步骤的耗时和 API usage。

### 阶段 2：本机模式

再部署 Windows 原生 ComfyUI + SDXL 修补工作流，用同一组测试图片对比编辑质量、响应时间、显存峰值及 Qwen 恢复时间。若效果与稳定性可接受，再提供本机后端切换；否则保留云端作为默认编辑服务。

OpenAI API 可作为第三个候选后端，在实际调用成本、人物/原图细节保持能力和输出质量有需求时，再做同样的基准对比。

## 建议的首版范围

- 仅在群聊 `@机器人` 且出现明确修图意图时创建编辑任务。
- 支持每个任务一张输入图片、一次编辑、一张输出图片。
- 修改要求和图片可同条或分条到达，但必须来自同一群、同一发送者，并处于有效期内。
- 不改动现有私聊分段逻辑、普通群聊回复逻辑、模型切换和现有识图/搜索功能。
- 首版不做多轮迭代、区域涂抹 UI、多图合成或自动联网找参考图。

## 验收标准

- 未 @ 机器人或未出现修图意图时，不会启动图片编辑。
- 不同群友同时发起任务时，图片和修改要求不会串配。
- 同一发起者的文字与图片无论同条或分条到达，都能按规则配对；超时后图片不会再触发旧任务。
- 编辑成功时机器人能在原群聊发送结果图；编辑失败时有明确失败回复，普通消息处理仍可继续。
- 日志记录任务 ID、队列等待时间、模型处理时间、回传时间、后端名称和失败原因；不在普通日志中输出 API Key。
- 用固定测试集记录本机模式的成功率、P50/P95 完成时间、峰值显存和与 Qwen 并行时的稳定性。
