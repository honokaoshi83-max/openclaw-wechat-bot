# 本地微信图片修改功能设计

## 目标

让微信群成员通过 @机器人 申请修图，再发送修改要求和一张图片；本机模型修改图片后，由微信 Hook 将新图发回原群。所有输入图片都留在本机处理，不使用图片编辑云 API。

## 用户流程

1. 群成员 @机器人 并说“帮我修图”“修改一下图片”等，机器人回复“请说出修改需求并发送图片。”
2. 机器人按群 ID 和发送者 ID 建立 5 分钟待处理任务。
3. 发起者可在一条或多条后续消息中给出要求、发送一张图片；后续消息不强制再次 @。
4. 图片和要求匹配后进入全局单任务队列，原图不覆盖，生成结果以新图片发送回群。
5. 成功、失败、取消或超时后清理待处理状态。失败时返回可理解的错误提示。

## 架构

- 本机部署 Windows 版 ComfyUI AMD 后端，监听仅限 `127.0.0.1` 的独立端口 `8188`。
- 首版使用 InstructPix2Pix FP16 checkpoint 进行指令式整图编辑；不实现区域蒙版、擦除/补画、超分或多轮修改。
- 微信桥接新增图片编辑状态管理、单并发队列、ComfyUI HTTP 客户端和 `/SendImgMsg` 回传。
- ComfyUI 与现有 llama.cpp/OpenClaw 服务隔离。模型只在任务执行时加载；检查 GPU 忙闲，编辑期间串行化本地模型任务，避免显存争用。
- 上传、输出仅使用项目运行时目录。输入文件在任务后清理；输出图留在短期 outbox，保证 Hook 异步发送有时间读取。
- 限制图像大小、像素上限、编辑耗时、任务队列长度；服务不可用时快速失败，不阻塞普通消息。

## 非目标与约束

- 不修改个人对话分段、现有图片识别、DeepSeek、搜索、离线规则或微信 Hook DLL。
- 不覆盖/删除原图，不自动发送用户图片到外部网络服务。
- 不以自动更新或提权方式安装 AMD 驱动；安装需要系统重启的驱动时停止并报告，不尝试远程绕过。
- Windows AMD PyTorch/ComfyUI 的 GPU 路径存在实验性兼容风险；启动与推理要有健康检查及 CPU/错误回退提示。

## 验收标准

- 修图请求会创建按群与发送者隔离、可过期的待处理任务。
- 非发起者图片不能匹配；一个请求最多编辑一张图。
- ComfyUI API 客户端能上传图、提交 workflow、等待完成并取回图片；超时和失败会清理临时文件。
- Hook 回传请求参数经本地测试覆盖，运行时只向已登录 AI 账号发送。
- 原有桥接单元测试全部通过；完整本机推理实测记录耗时、分辨率和失败原因。
- 不启用新服务的情况下，现有聊天和视觉服务继续可运行。
